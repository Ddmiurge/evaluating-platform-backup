## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 要做什么 | **论文→能力转换 Agent**：发现安全评测相关论文/开源实现 → 按平台载体契约拆解映射 → 产出**可审草稿**（YAML 插件 / 文本·代码策略 / Skill / 内嵌插件包）→ 经**既有三道门**放行 |
| 可行性结论 | **方向成立，但必须是「草稿生产者」而非「发布者」**。平台已有 8 个手工转换先例（CC-BOS / AutoDAN / GPTFuzzer / FigStep / MM-SafetyBench / HADES / PromptInject / CipherChat）证明「论文→平台能力」路径可行；该自动化的是**草稿生成与查重**，不是放行 |
| 最大约束 | **生成期靶机反馈在现有契约下不可表达**（实测，见 §3）：Skill 运行时只有 `MACLAW_LLM_*` 生成模型凭据，现有 AutoDAN/GPTFuzzer Skill 均为「无靶压平版」（运行时源码明写禁止 `call the target model`）；忠实实现只能落第 3 级（内嵌插件，评测期挂钩子）或未来新增契约 |
| 治理归属 | Agent 产物与专家手工上传**同进同一状态机**（`pf_plugin` / `pf_strategy` / `pf_plugin_embedded` / Skill Hub），**不建第四条发布路径**；自动关卡、人工初审、构建验收、测试白名单、最终通过一关不豁免 |
| 可度量性 | conversion 质量从第一天可量化：自动关卡首过率 / 初审「需修改」率 / 真跑非零探针率 / 判据归属正确率（平台已在记 rejection hints、`judge_sources`、探针计数，基线免费） |
| novelty 在哪 | 不是「agent 找论文写代码」（literature-review agent 已一大把），是**闭环**：research → 可执行包 → 真实评测平台 → 真靶验证 → 治理放行，每一环有机器可判的判据 |
| 与 7 方向的关系 | 本稿是**新能力供给的乘法器**：方向 1–6 都需要新能力持续进目录，Agent 批量生产它们的草稿；不替代其中任何一个 |

## 1. 创新方向盘点（本稿在路线图里的位置）

第一轮讨论盘点的 7 个方向（详述见会话记录，此处压缩为索引）：

| # | 方向 | 一句话 | 现有地基 | 与本稿关系 |
|---|---|---|---|---|

| 2 | 攻击资产沉淀 + 回归/复现 | 成功 payload 一键固化为 composed_attack；换模型版本回归；复现确认 | 报告已带原文；批量链路可按指定载荷重跑（机制现成） | 独立方向 |

## 2. 为什么必须评审制（第 3 级模型回顾）

平台按**危害上限**决定治理强度（`embedded-plugin-track.md` §2）：

| 级 | 载体 | 危害上限 | 治理 | 自助度 |
|---|---|---|---|---|
| 1 数据 | YAML 插件 / 文本策略 / 数据包 | 污染结果（可归因可停用） | 事后治理 | 完全自助 |
| 2 盒中代码 | JS 策略（纯函数盒） | 被盒子圈住 | 运行时闸（开关+专属实例） | 自助发布 |
| 3 本体代码 | **内嵌插件**（读响应、挂钩子、可编排） | **进程沦陷（能偷）** | **事前人审+构建验收** | 上传自助、放行评审 |

关键事实：内嵌插件**没有运行时门**（promptfoo 编译期 API 无运行时加载口，只能烤进镜像）——闸只能建在「进镜像之前」，这正是三道门的由来。**Agent 不改变任何一级的治理强度**：它的产物按危害上限对号入座，绝不旁路。

## 3. 可行性评估（分环节）

| 环节 | 可行性 | 理由 |
|---|---|---|
| 论文/代码**发现与跟踪** | 高 | 纯检索+摘要；能力清单可做「新论文 vs 既有能力」查重 |
| 论文 → **载体分类** | 高 | 载体分类学现成（§4），分类任务 agent 擅长 |
| 论文 → **YAML 插件草稿**（generator+grader） | 中高 | 模板/判据类攻击可自动生成；grader 极性（必须写安全侧陈述）是已知坑，需自检 |
| 论文 → **Skill 草稿**（真算法） | 中 | 伪代码→可跑代码的调试会反复碰壁；需靶机反馈的算法受 §3.1 分水岭约束 |
| **全自动发布到生产** | 低，且不该做 | 见 §5 风险 1/2；与三级放开模型直接冲突 |

### 3.1 分水岭实测（2026-11-05 源码核对，决定分类规则怎么写）

现有 8 个 Skill 全部是**生成期无靶**的压平版：

- `autodan-stealth-skill/runtime/main.py:185`：*"Do not download local models, run genetic optimization, **call the target model**, or judge success."*
- `gptfuzzer-mutator-skill/runtime/main.py:185`：*"Do not call or simulate the target model."*

即：**需要靶机反馈的算法（AutoDAN 遗传优化、GPTFuzzer energy 调度、TAP/PAIR 树搜索）在现有 Skill 契约下无法忠实实现**——Skill 运行时只有租户生成模型凭据，平台批量链路是「先生成、后执行」，生成期没有反馈回路。当初转换时把论文「压平」成了 LLM 一次性改写，且提示词里显式禁止调靶（这是正确处置：凭据边界使然）。这一事实直接决定 §4.3 的决策程序：**忠实版靶机反馈算法只有一个合法落点——第 3 级内嵌插件（评测期挂钩子），或未来的新契约（生成期可代理调靶，需独立立项评估凭据面）**。

## 4. 载体选择：拆解 + 对号入座（核心设计）

### 4.1 六种载体的契约表

| 载体 | 契约（能表达什么） | 表达不了什么 | 治理档 |
|---|---|---|---|
| **数据包**（sample/template/composed_attack） | 静态载荷语料，模板可带 `{{sample}}` 占位 | 任何每轮需新鲜生成的东西 | 1 级 |
| **YAML 插件**（pf_plugin） | `generator`（LLM 按 purpose 现场生成 n 条探针）+ `grader`（每条探针的 llm-rubric 判据） | 任何「逻辑」：算法、状态、条件变换；判据只能是 rubric 文本；grader 里只有 `{{purpose}}` 可用 | 1 级 |
| **文本策略**（pf_strategy yaml） | 对已生成探针做 **LLM 支撑的改写/多轮编排**（strategyText + maxTurns），可与任意插件组合 | 确定性算法（无 LLM 的编码/重排） | 1 级 |
| **代码策略**（pf_strategy js） | **纯函数** `testCases → testCases`：自定义编码、条件变换、确定性重排；禁网禁 LLM | 任何需要模型或靶机的东西 | 2 级（专属实例闸） |
| **Skill**（Hub 可执行包） | 整条生成流水线：吃样本 → 调租户 LLM 批量生成 → 吐 `payload_dataset`（可带图）→ 平台执行判定 | **生成期靶机反馈**（§3.1）；执行/判定仍归平台 | Skill 轨（Hub 发布 + 租户安装） |
| **内嵌插件**（P28，编译进引擎） | **读响应、挂钩子、可编排**——新判分逻辑、评测期内自适应编排 | 无（但 3 级：人审+构建验收） | 3 级 |

### 4.2 两个结构性事实（约束选择）

1. **两条执行链不混用**：引擎链（插件×策略）与 Skill 链（payload_dataset→批量执行）一次 run 只走一条。一篇论文若同时贡献「新攻击维度」和「新生成算法」，不能拆成插件+Skill 塞进同一次评测——选主载体，或拆成两个独立能力。
2. **策略可组合、插件×策略正交两轴**：`探针数 = num_tests × 策略数`，多策略可同时选。**正交贡献可以拆**（如「新编码」+「新话术升级」= 一个代码策略 + 一个文本策略，同 run 叠加）。

### 4.3 五轴决策程序（agent 的分类器）

```
① 拆贡献：论文 = {攻击内容/语料, 变换方法, 生成算法, 判定逻辑, 编排/评估框架} 的子集
② 查重：每个部件先对既有目录（116 插件 + 27+9 策略 + 8 Skill + 能力清单）
   ——已存在 → 不产出，报告「已被 X 覆盖」（防 P3-1 式重复造词汇）
③ 逐部件映射（按表达力从低到高试，够用即止）：
   静态语料？              → 数据包
   纯提示词/包装模板？      → YAML 插件 generator（新判据 → 同包 grader）
   LLM 改写/多轮话术？      → 文本策略
   确定性算法（编码/重排）？  → 代码策略
   需批量 LLM 生成流水线/出图？→ Skill
   需读响应/评测期编排/新判分机制？→ 内嵌插件（3 级，交人裁决）
④ 靶机反馈检查（分水岭，见 §3.1）：
   生成期需要目标回答？→ 三条路，必须显式选一条并如实标注：
     a) 压平版（现有 8 个 Skill 的做法）：LLM 代替靶机做指导，报告注明「非原算法」
     b) 换载体：把反馈推迟到评测期——能表达为多轮策略/固定升级路径 → 引擎链
     c) 忠实版 → 内嵌插件（3 级）——唯一能「读响应」的档，也正是它在人审门后的理由
⑤ 模态检查：含图 → 只有 Skill 能带 images[]（引擎链是纯文本）
```

**两条硬约束**：

- **表达力优先、治理成本次之**：从低档往高档试，够用即止（YAML 够用就别上 Skill，Skill 够用就别上内嵌——3 级评审带宽是稀缺资源）；但**绝不为省成本降格表达**——把算法硬塞进 YAML 正是「绿跑零覆盖」（U6 形态）的制造机。
- **判定载体单独检查**：攻击能生成 ≠ 能判对。rubric 文本能写 → YAML grader；要结构化计算/新判分机制 → 内嵌插件；**想新增 `judge_profile` 是平台改动，不是专家包**（那是平台自有词汇表，agent 不许碰——P3-1 教训的镜像）。

### 4.4 fidelity 字段（诚实性设计，agent 输出必填）

压平不是失败，**压平而不声明才是**——否则报告会声称测了 AutoDAN，实际测的是 LLM 改写。agent 的每条映射必须携带：

```yaml
paper: "PAIR: ..."
decomposed:
  - part: tree-search generation algorithm
    needs_target_feedback: true          # ← 分水岭字段
    carriers_tried: [yaml, text_strategy, skill]   # 为什么都不够
    chosen: embedded_plugin | flattened_skill
    fidelity: faithful | flattened(丢弃了XX)
  - part: judge rubric for "partial compliance"
    chosen: yaml_grader
coverage_check: {native_base64: already_covered, ...}
one_chain_note: 两部件分属引擎链/Skill 链，不可同 run —— 主载体=...
```

### 4.5 对号入座示例（拿真实论文/现有能力验规则）

| 论文/能力 | 主载体 | 理由 |
|---|---|---|
| AdvBench / JailbreakBench 语料回放 | 数据包 | 静态，无生成 |
| CipherChat（密文对话包装） | 文本策略（现有做成了 Skill，因要走专家样本流水线） | LLM 改写整段对话 |
| Base64/hex 编码类 | **不产出**（promptfoo 原生已有） | 查重直接命中 |
| FigStep / MM-SafetyBench | 多模态 Skill | 出图，引擎链无此表达力 |
| GPTFuzzer 变异算子 | Skill（压平版，已做） | 变异靠 LLM；原论文 energy 反馈调度丢弃并已声明 |
| AutoDAN 遗传优化 | 压平版 Skill（已做）/ 忠实版=内嵌插件 | GA 需靶机评分——分水岭实例 |
| TAP/PAIR 树搜索 | 同上，忠实版只能内嵌 | 生成期强靶机反馈 |
| 新判分标准（rubric 可写） | YAML grader；要计算 → 内嵌 | 判定载体单独判 |
| 新评测编排（边测边改配置的 harness） | 内嵌插件 | 「可编排」是 3 级的定义性能力 |

## 5. 风险与防线

| # | 风险 | 处置 |
|---|---|---|
| 1 | **静默失败形态回归**（U6 绿跑零覆盖 / P2-1 非法 id / 缺 config）——agent 批量产出天然携带这些形态 | 产物**只走正常发布路径**，全部过存储出口既有闸；**禁止任何「agent 直达通道」**（写进设计稿红线，评审时点名检查） |
| 2 | **agent 自身是供应链风险面**（拉取任意 GitHub 仓库并理解/改写） | 执行环境隔离；拉取的代码**绝不在平台侧执行**；「读懂后重写」而非复制粘贴（顺带解决 research-only license）；执行只发生在包内测试（零依赖离线、引擎子进程限时）与测试白名单 run |
| 3 | **「论文声称有效」≠「在你的目标上有效」** | 测试中白名单真靶 run 是验收证据；没看过测试 run 不进全员目录（P28 状态机已内置） |
| 4 | **P3-1 词汇表负债重演**（agent 为凑数发明攻击维度） | 能力清单做查重基线；「新类别」打标交人裁决；agent 不得新增平台词汇（策略/插件/judge_profile） |
| 5 | **评审带宽稀释**（agent 产速 > 人审带宽） | 治理成本次之原则 + conversion 四指标持续压「需修改」率；Phase 2 预检把机器可判问题挡在人审之前 |

## 6. 分阶段路线

| 阶段 | 内容 | 落地形态 | 不做 |
|---|---|---|---|
| **Phase 1（纯文本，零执行）** | 文献监控 + 载体分类 + 草稿生成（YAML 插件 / Skill 骨架 + 溯源：论文、license、改写 diff 摘要）→ 进「待初审」 | 专家门户 Skill（如 `paper2plugin-drafting`）或 MaClaw 工具集——现有 agent loop + MCP 工具即可撑起 | 不执行任何拉取代码 |
| **Phase 2** | 接入自动关卡预检：草稿先自过静态扫描+零依赖测试再提交，压初审「需修改」率 | 复用 `pf_plugin`/`pf_plugin_embedded` 存储出口闸 | 不改闸的判定逻辑 |
| **Phase 3** | 接入测试中白名单真靶验证：agent 拿测试 run 结果自我迭代草稿 | 复用 P28 状态机「测试中」阶段 | 迭代终点仍是人工初审，不豁免任何关卡 |
| **永不** | — | — | **auto-approve / auto-build / auto-publish** |

## 7. 度量（conversion 质量四指标，第一天出数）

| 指标 | 定义 | 基线来源 |
|---|---|---|
| 自动关卡首过率 | 草稿上传一次通过静态扫描+包内测试的比例 | rejection hints 结构化记录 |
| 初审「需修改」率 | 人工初审打回的比例（压它 = Phase 2 的存在理由） | `maclaw_plugin_package_reviews` |
| 真跑非零探针率 | 选中后真跑产出 ≥1 条探针的比例（零覆盖 = 降格硬塞被抓） | 探针计数（`Totals.Probes`） |
| 判据归属正确率 | findings 的 `judge_source` 落在 `custom:<handle>`/正确家族的比例 | `judge_sources` |

另：8 个手工先例就是现成的**标注集**——拿它们回放分类器，载体判定与人工一致率是第一份验收报告。

---

## 8. 验收判据（每条先跑红）

1. **分类正确性**：8 个先例回放，载体判定与人工判定一致（先例本身是已知答案）；
2. **查重**：对已覆盖能力（如 base64 策略）必须报 `covered` 而非产出草稿——重复造轮子率 = 0；
3. **fidelity 声明**：所有 `needs_target_feedback=true` 的部件必须显式 chosen 路径 + fidelity 值，压平必须列出丢弃内容；
4. **治理不豁免**：agent 草稿与手工上传在同一条发布路径上，任何关卡拒绝的码与文案同源（`TestFrontend*` 镜像守卫照常覆盖）；
5. **度量可回读**：四指标从第一批草稿起出数，且与手工上传基线可对比（手工上传是对照组）。

## 9. 非目标

| 不做 | 理由 |
|---|---|
| 第四条发布路径 / agent 直达执行 | 与三级放开模型冲突，静默失败形态会回来 |
| 全自动放行 | 第 3 级危害上限（进程沦陷）决定人审不可省；1/2 级也需先证明 conversion 质量 |
| 新增平台词汇（策略 id / 插件 id / judge_profile） | P3-1 两套词汇表之债是既定教训 |
| 本稿内实现 Phase 1–3 | 只定契约与判据；实现另行立项（先过评审） |

## 10. 与导师 idea 的对照（采纳 / 修正各一处）

- **采纳**：「agent 自动寻找论文、找开源代码、改装成插件」的方向判断——平台 8 个手工先例证明路径成立，自动化草稿生成有真实价值；
- **修正**：「改装成插件」不能理解为「agent 产出即可用」——必须是「草稿生产者 + 既有评审制消费者」，且**载体不是只有插件一种**（§4 六载体契约表是本稿对原 idea 最大的补充：按表达力拆解映射，而不是一律变插件）。

> 待评审事项：Phase 1 落地形态（专家门户 Skill vs MaClaw 工具集）、8 先例回放标注由谁做、fidelity 字段是否进报告（建议只进映射报告、不进评测报告）。
