## 1. 目标与范围

**目标**：为"评估平台 + promptfoo 合并"项目设计合并后三门户的完整前端页面层级树，并对所有新增/扩展页面给出页面级设计（布局、交互流、组件清单、接口对接、复用关系）。

**范围**：
- 覆盖企业门户 / 专家门户 / 管理员门户全部页面（既有页面全部保留）。
- 新增 5 个页面：自选评测向导页（企业，菜单名「自选评测」）、评测报告列表页（企业，菜单名「评测报告」）、评测报告详情页（企业）、插件发布页（专家）、引擎服务治理页（管理员）。
- 扩展既有页面：聊天工作台（plan_confirm 卡 / progress 卡 / report 卡增强）、计费管理、评测与任务治理、系统健康，以及三门户侧边栏菜单。
- 登录与路由守卫层保持既有结构，仅新增路由挂载。

**不做**（遵循文档 2 决策 6）：
- 不嵌入 promptfoo Web UI（不做 iframe / 微前端）。
- 不引入 zustand/radix/tailwind 等 pf UI 技术栈，全部用平台 antd 6 + CSS 变量 token 重写。
- 不改动任何后端代码；本设计的接口仅为 BFF 侧新增 API 的**前端消费契约**（后端归属见文档 2 Phase 0-2）。

### 2.3 聊天工作台核心卡片（`ChatCards.tsx`，本次增强对象）

- **PlanConfirmCard**（card_type=plan_confirm）：行式字段（任务名称/评估目标/目标类型/目标地址/模型/资源模式/选择策略）+ 评估类型 Tag 组（`LABELS`）+ 使用能力 Tag 组（绿色，`displayCapabilityName` 解析 `skillhub:` / `sample:` / `template:` / `composed_attack:` 前缀）+ 选择理由 + 测试问题数 InputNumber + 确认执行按钮。
- **ProgressCard**（card_type=progress）：Progress 进度条（`progressPercent` 阶段回退百分比 + planned/executed 计数）+ `PROGRESS_STAGE_LABELS` 中文阶段名 + 状态文案。
- **ReportCard**（card_type=report）：风险等级（`RISK_COLORS`/`RISK_LABELS`）+ 安全分 + 摘要 + PDF 下载（`reportService.downloadMaclawReport` + `triggerBrowserDownload`）。
- **WelcomePanel**：能力卡（tone: attack/governance/engine/tool 四种视觉，`capabilityVisual`）。

### 2.4 服务层模式（新增服务必须遵循）

- `services/api.ts`：axios 实例 + JWT 拦截器（`/api/v1` 前缀）。
- `services/maclawRuntime.ts`：`maclawRuntimeChatService`（createSession / sendMessage / listSessions / confirmPlan / listEvaluationTargets / saveEvaluationTarget / probeEvaluationTarget）+ **手写 SSE 消费**（fetch + ReadableStream + `parseSSEBlock` 按 `\n\n` 切块 + `isTerminalEnvelope` 终态判定），返回取消函数。
- `services/report.ts`：PDF/markdown/json 导出 + 浏览器下载。
- `services/expert.ts` / `services/admin.ts` / `services/billing.ts`：REST 封装 + 类型定义，方法即端点，`.then(r => r.data)` 风格。

### 2.5 主题 token（`styles/theme.css`，新页面必须复用）

```
--bg-base #f6f7f9 / --bg-surface #ffffff / --bg-card #ffffff / --bg-hover #f2f6fd
--color-primary #2563eb（hover #3b82f6 / active #1d4ed8 / light rgba(37,99,235,.10)）
--text-primary #0f172a / --text-secondary #475569 / --text-muted #94a3b8
--border-color #e2e8f0（原型统一取 #e5e7eb 细边框）
--color-critical #dc2626 / --color-high #ea580c / --color-medium #d97706 / --color-low #16a34a / --color-info #0284c7
```

风险色语义与 ChatCards 的 `RISK_COLORS`/`RISK_LABELS` 一致（critical/high/medium/low + 中文标签），引擎结果页直接沿用同一套语义，保证与聊天链路报告卡视觉一致。

#### 6.1.2 核心交互流（状态机）

```
页面级状态机:
  step: 1(purpose) → 2(capabilities) → 3(target) → 4(confirm) → 5(progress)
  规则: 每步「下一步」前做本地校验（见下），不通过则禁用按钮并标红；
        Step2→Step3 要求 plugins.length ≥ 1；Step3→Step4 要求已选/已建目标；
        Step4→Step5 由「确认并启动」触发 POST run（Modal 二次确认含费用）。

run 级状态机（与 BFF /engine/redteam/runs/:id 的 status 对齐）:
  queued → generating_tests → executing_probes → engine_judging
         → compiling_report → succeeded
  任意态 → failed / canceled
  前端消费: SSE 流式更新（优先） / 5s 轮询 getRun（SSE 断开降级）
  恢复: localStorage["engine-wizard-run-id"] 存进行中 run；重进页面时
        getRun 恢复进度；终态后清除并提示查看报告。
```

每步校验规则：
- Step1：purpose 非空且 ≥ 20 字符；numTests ∈ [1, 50]；合规框架可空。
- Step2：plugins ≥ 1（strategies 可空 = 不做变换）；单插件 numTests 覆盖值 ∈ [1, 50]。
- Step3：选定 target_id 或新表单完整（name/base_url/kind 必填；新建走既有 saveEvaluationTarget）。
- Step4：judge_mode 必选；余额 < 预估费用 × 1.2 时阻断并给出充值链接。

#### 6.1.4 数据接口对接（services/engine.ts，遵循既有 axios 模式）

```ts
// Step2 —— 能力目录（BFF 聚合 capability_catalog 扩展 + 引擎插件元数据）
engineService.getCatalog(kind: 'plugin' | 'strategy', params?: { search?: string; category?: string })
  → GET /api/v1/engine/capabilities?kind=plugin
  ← { items: Array<{ id: string; label: string; description: string; category: string;
       configurable: boolean; param_schema?: object; source: 'builtin' | 'custom';
       risk_category?: string }> }

// Step4 —— 预估（BFF 调引擎 estimate 或本地按目录条数估算）
engineService.estimate(payload: { purpose: string; num_tests: number;
    plugins: Array<{ id: string; config?: object }>; strategies: Array<{ id: string; config?: object }> })
  → POST /api/v1/engine/redteam/estimate
  ← { estimated_probes: number; estimated_duration_seconds: number;
      estimated_tokens: { generation: number; judging: number; target: number };
      estimated_cost: { total: number; generation: number; judging: number; target: number } }

// Step4→5 —— 创建运行
engineService.createRun(payload: { purpose: string; num_tests: number;
    plugins: Array<{ id: string; config?: object }>; strategies: Array<{ id: string; config?: object }>;
    target_id: string; judge_mode: 'auto' | 'promptfoo_native' | 'platform_rejudge' })
  → POST /api/v1/engine/redteam/runs
  ← { run_id: string; status: 'queued' }

// Step5 —— 状态/SSE/取消
engineService.getRun(runId)            → GET /api/v1/engine/redteam/runs/:id
engineService.cancelRun(runId)         → POST /api/v1/engine/redteam/runs/:id/cancel
engineService.streamRunEvents(runId, onMessage, onDone, onError): () => void
  → GET /api/v1/engine/redteam/runs/:id/events   （SSE，事件信封复用既有
    parseSSEBlock 模式：{ snapshot: { engine_event: { phase, status_text,
      planned_count, executed_count, current_stage, duration_ms } } }）
```

错误处理：SSE 中断 → 退避重连 3 次 → 降级 5s 轮询 `getRun`；createRun 余额不足（HTTP 402）→ message.error + 跳 `/enterprise/billing`；引擎不可用（503）→ Alert 提示联系管理员。

## 8. 前端服务层 `services/engine.ts` 完整契约

```ts
import api from './api'

export type JudgeMode = 'auto' | 'promptfoo_native' | 'platform_rejudge'

export interface EngineCapability {
  id: string
  label: string
  description: string
  category: string
  kind: 'plugin' | 'strategy'
  configurable: boolean
  param_schema?: Record<string, unknown>
  source: 'builtin' | 'custom'
  risk_category?: string
}

export interface EngineRunProgress {
  phase: 'queued' | 'generating_tests' | 'executing_probes' | 'engine_judging'
        | 'compiling_report' | 'succeeded' | 'failed' | 'canceled'
  status_text?: string
  planned_count?: number
  executed_count?: number
  current_stage?: string
  duration_ms?: number
}

export const engineService = {
  getCatalog: (kind: 'plugin' | 'strategy', params?: { search?: string; category?: string }) =>
    api.get('/engine/capabilities', { params: { kind, ...params } }).then(r => r.data),

  estimate: (payload: EngineEstimateInput) =>
    api.post('/engine/redteam/estimate', payload).then(r => r.data),

  createRun: (payload: EngineRunInput) =>
    api.post('/engine/redteam/runs', payload).then(r => r.data),

  getRun: (runId: string) =>
    api.get(`/engine/redteam/runs/${runId}`).then(r => r.data),

  cancelRun: (runId: string) =>
    api.post(`/engine/redteam/runs/${runId}/cancel`).then(r => r.data),

  streamRunEvents: (runId: string, onMessage: (p: EngineRunProgress) => void,
                    onDone: () => void, onError: (e: Error) => void): () => void,
  // 实现与 maclawRuntime.streamRunEvents 同构：fetch SSE + parseSSEBlock + 终态判定

  listReports: (params?: { limit?: number; offset?: number; search?: string }) =>
    api.get('/engine/redteam/reports', { params }).then(r => r.data),

  getReport: (reportId: string) =>
    api.get(`/engine/redteam/reports/${encodeURIComponent(reportId)}`).then(r => r.data),

  exportReport: (reportId: string, format: 'csv') =>
    api.get(`/engine/redteam/reports/${encodeURIComponent(reportId)}/export`,
            { params: { format }, responseType: 'blob' }).then(r => r.data),
}
```

类型 `EngineEstimateInput` / `EngineRunInput` / `EngineReport` 的字段即 §6.1.4、§6.2.2 定义，不重复。

## 10. 状态与错误处理约定

| 场景 | 处理 |
|---|---|
| 引擎服务不可用（503/超时） | 向导 Step2/Step5 显示 `Alert`（引擎暂不可用，请联系管理员），能力目录加载失败给重试按钮；不阻断既有聊天链路 |
| createRun 余额不足（402） | `message.error('余额不足，请先充值')` + 按钮`去充值`跳 `/enterprise/billing` |
| SSE 中断 | 指数退避重连 3 次 → 降级 5s 轮询 `getRun`；轮询与 SSE 终态一致才停止 |
| 用户中途关闭/刷新向导 | localStorage 记录 run_id；重进恢复 Step5；终态清除 |
| 任务失败 | Step5 切 `Result status="error"` 展示脱敏 `status_text` + 重试按钮（重新 createRun，沿用表单状态） |
| 任务取消 | 二次确认；已消耗部分计费提示 |
| 报告不存在/无权限 | 详情页 `Result 404` + 返回列表 |
| 目录为空/无已选插件 | Step2 右侧 `Alert` 警告 + 下一步禁用 |
| 浏览器红线 | 引擎产物原文（prompt/response）永不进入前端：所有接口仅返回计数、severity、脱敏 reason（`top_reasons` ≤3 条/插件，服务端截断） |
