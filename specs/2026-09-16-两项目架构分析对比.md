## 1. 评估平台架构总结（架构笔记 + 源码验证）

### 1.1 定位与形态

大模型安全红队评测平台：企业用户提供被测模型，平台通过攻击载荷并发测试、判定、产出中文 PDF 报告。形态 = **企业门户 + 专家门户 + 管理员门户 + maclaw BFF**。

核心分工：**MaClawSrv = 大脑**（外部 LLM Agent 编排服务，决定测什么、怎么测）；**本仓库 Go 后端 = 手 + 门卫**（真正调被测模型、判分、存证据、出报告 + 全部安全边界）；**前端 = 脸**。

### 1.2 技术栈与模块划分

| 层 | 技术 | 规模 | 关键路径 |
|---|---|---|---|
| 前端 | React 19 + Vite + antd 6，SPA | 约 6800 行 | `evaluating_platform/frontend/src/`（pages/enterprise|expert|admin、services、context） |
| 后端 | Go 1.25 + gin，模块化单体 | 约 2.1 万行非测试 + 1.16 万行测试 | `evaluating_platform/internal/`（api 33 文件 / maclaw 36 文件 / repository 16 / model 12 / billing / sample / crypto） |
| 存储 | PostgreSQL（25 migration）+ Redis + MinIO | — | `migrations/`、`pkg/storage` |
| 编排 | docker compose 七容器 | postgres/redis/minio/minio-init/maclaw-runtime/hubcenter/backend/frontend | `docker-compose.yml` |

依赖方向严格单向：`api → maclaw/billing/sample → repository → model`。**架构红线：所有 MaClawSrv API 认知锁死在 `internal/maclaw` 防腐层内**（36 文件）。

### 1.3 核心评测链路（一条评测的完整数据流）

```
1. 企业用户在聊天工作台描述评估需求
2. BFF（internal/api → internal/maclaw）解析账号→maclaw 租户（instance_resolver.go），
   设置 agent_profile=redteam_evaluation_v1，代理给 MaClawSrv（maclawsrv_client.go，931 行）
3. MaClaw 对话澄清 / 检索专家数据 / 检索已安装 Skill
4. MaClaw 返回 response_source=plan_confirm 结构化计划卡
   （目标摘要+风险类型+建议 test_count+选中能力+选择理由）
5. 用户确认 → POST /api/v1/maclaw/evaluation/sessions/:id/confirm
6. BFF 准备计划卡选中资源/Skill backfill → MaClaw 创建 evaluation.run job
7. Skill-backed：MaClaw manage_skill(run) → register_skill_payload_dataset 注册服务端临时 handles
8. MaClaw 调 MCP bridge 的 execute_redteam_evaluation_batch（并发默认 5）
   → 组合 payload → 并发调被测模型 → 规则快判+LLM 判定 → 存证据 → 编译中文报告
9. 前端 SSE/轮询展示进度卡（planned_count/executed_count/current_stage/duration_ms）
10. 报告卡出现 → 下载 PDF
```

### 1.7 关键数据表

### 1.8 平台硬约束（合并必须尊重，来自 AGENTS.md）

1. 评测执行引擎在 MaClawSrv——本仓库不重新引入评测引擎（**合并方案必须正面回答此条与"平台引入 promptfoo 引擎"的关系**）
2. `internal/maclaw` 是唯一 MaClaw API 认知边界
3. 浏览器永远拿不到 secret/payload 原文/evidence content/本地路径
4. 每个平台账号对应独立 maclaw 租户
5. 旧 API 只留 410 Gone tombstone

## 5. 核心结论

1. **两者几乎无重复建设**：平台价值在"企业级治理壳"（多租户/计费/加密/中文报告/Agent 编排 BFF），promptfoo 价值在"红队引擎内核"（生成广度+目标广度+判定深度）。合并本质是**壳×内核**组合，不是二选一。
2. **最大架构冲突只有一处**：AGENTS.md 规定"评测执行引擎在 MaClawSrv"，而 promptfoo 自带引擎。解法是把 promptfoo 定位为**平台工具层之后的执行引擎服务**（MaClaw 仍是决策大脑，promptfoo 成为新的"手"），详见文档 2。
3. **promptfoo 自带 MCP server**（commands/mcp）与平台"MaClaw 通过 MCP bridge 回调工具"的集成语言天然同构，是最低摩擦的集成通道。
4. promptfoo 的 remote generation 默认可外发 promptfoo 官方云，**企业化部署必须自托管端点或强制禁用**（开关已具备），这是安全合规硬要求。
5. 判定系统是唯一需要"语义层融合"（而非工程拼接）的领域：平台 CC-BOS 阈值制与 pf rubric 制输出结构不同（attack_score/result vs pass/score/severity），需双轨过渡。
