## 3. 现在能做什么

**企业**

- 连接被测目标：OpenAI 兼容 LLM，或自定义 HTTP 智能体（模板 + 响应路径，探活与真实调用同形）；
- 对话式评测：描述需求 → 计划卡（插件轴 / 策略轴分开展示，可 `×` 移除、可追加策略）→ 确认 → 报告卡 + PDF；
- 自选评测：直接选插件/策略，插件/策略下拉含「专家发布」分组；
- 报告：逐条攻击载荷与目标回答、判定理由、指标（攻击成功 / 攻击失败 / 未取得回答分开计数）、评分依据行。

**专家**

- 样本 / 模板 / 组合攻击管理；Skill 与 MCP 服务；
- 自定义**插件**与**策略**发布（仅 YAML），支持对同一包「重新发布」（按 id 更新，不新增）；
- Hub 发布与 Skill 分发。

**管理员**

- 模型配置（平台默认 + 账号覆盖）；账号/租户；健康摘要；
- 资源治理：自定义插件**与**策略的启停 / 归档，即时生效。

**引擎执行语义（都已上机验证）**

- 只走 promptfoo 原生生成（Plan A 已删除）；
- 逐插件 rubric 判分；判定口径文案区分「谁判每条」与「谁汇总」；
- 策略包装不额外跑一遍无策略对照组；探针数 = `num_tests × 策略个数`；
- 目标调用失败分类为可读短语，不泄漏内网地址/引擎路径/堆栈；
- 自定义插件/策略经 `pf_plugin:` / `pf_strategy:` 引用，两条入口（向导、计划卡）同一解析器。

## 5. 下一步（建议顺序）

1. **P12 + P13 上机验证**：
   - P12：下架后企业下拉消失、旧计划卡 confirm 被拒、专家列表状态正确、管理员归档同步资源行；
   - P13：成功项不再显示「未取得回答」、三数之和 = 总数、成功率 ≤100%；重复 confirm 两次靶机各收到一批请求；运行中刷新仍能看到进度卡；靶机挂住时按 `REQUEST_TIMEOUT_MS` 结束而不是永久占用 worker；引擎重启用 `--force-recreate`；
2. **部署脚本自检**：`df -h /var` 低于阈值即停；部署后探测引擎能否解析生成模型域名；
3. **混合场景上机验证**：用确定性靶机桩（前 N 次正常、之后拒连）补上唯一未上机的分支；
4. 目标侧 300 秒队列超时（Dify）—— 运维/靶机配置；
5. 体验与体积：报告卡摘要、PDF 字体子集化。

> 历史报告不回填：P13 之前落库的报告保持原读数（作为证据），新 run 生效。
