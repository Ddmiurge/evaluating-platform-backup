## 3. 现在能做什么

**企业**

- 连接被测目标：OpenAI 兼容 LLM，或自定义 HTTP 智能体（模板 + 响应路径，探活与真实调用同形）；
- 对话式评测：描述需求 → 计划卡（插件轴 / 策略轴分开展示，可 `×` 移除、可追加策略）→ 确认 → 报告卡 + PDF；
- 自选评测：直接选插件/策略，插件/策略下拉含「专家发布」分组；
- 报告：逐条攻击载荷与目标回答、判定理由、指标（攻击成功 / 攻击失败 / 未取得回答分开计数）、评分依据行。

**专家**

- 样本 / 模板 / 组合攻击管理；Skill 与 MCP 服务；
- 自定义**插件**与**策略**发布（插件仅 YAML；策略有文本/代码两形态，代码包受开关 `MACLAW_STRATEGY_CODE_PACKAGES` 控制，默认关闭），支持对同一包「重新发布」（按 id 更新，不新增）；
- 平台能力目录浏览（P23）：发布页主体即分组目录——内置插件按 promptfoo 原生类别分组、内置策略平组、全体专家已发布包并入「专家发布包」组，本账号发布的行特殊标注并保留重新发布/下架操作；**不显示发布者是谁**；
- Hub 发布与 Skill 分发。

**管理员**

- 模型配置（平台默认 + 账号覆盖）；账号/租户；健康摘要；
- 资源治理：自定义插件**与**策略的启停 / 归档，即时生效。

**引擎执行语义（都已上机验证）**

- 只走 promptfoo 原生生成（Plan A 已删除）；
- 逐插件 rubric 判分；判定口径文案区分「谁判每条」与「谁汇总」；
- 策略包装不额外跑一遍无策略对照组；探针数 = `num_tests × 策略个数`；
- 目标调用失败分类为可读短语，不泄漏内网地址/引擎路径/堆栈；
- 自定义插件/策略经 `pf_plugin:` / `pf_strategy:` 引用，两条入口（向导、计划卡）同一解析器。

## 5. 下一步（建议顺序）

1. **P24 上机验证**：策略发布页选 `.js/.mjs`/`.yaml/.yml` 文件 → 正文回显、超限/错扩展被点名拒绝、代码形态空 variant 时文件名建议填入；上机后立 45 号记录（P23 已由 44 号收口）；
2. **ai02 容器 DNS 长期修复**（43 号 §8.1）：当前引擎容器依赖 `/var/tmp/p22/docker-compose.dns.yml` 临时 override，下一次不带 `-f` 的重建会把生成链路打回全断；「compose 加 `dns:`」vs「宿主 `daemon.json`」二选一，需主理人拍板；
3. **`error_brief` 进 run DTO**（43 号 §8.3）：库里存了精确诊断但 API 只回错误码，用户看不到失败原因；两侧脱敏已各自完成，加字段不放宽规则；
4. **租户隔离 G-1~G-3**（`strategy-code-packages.md` §2.2）：策略代码包在共享部署开放的唯一硬前置（每租户引擎 / 租户级生成 key / 实例 token），需单独立项评估成本；
5. **部署脚本自检**：`df -h /var` 低于阈值即停；部署后探测引擎能否解析生成模型域名；
6. **混合场景上机验证**：用确定性靶机桩（前 N 次正常、之后拒连）补上唯一未上机的分支；
7. 目标侧 300 秒队列超时（Dify）—— 运维/靶机配置；
8. 体验与体积：报告卡摘要、PDF 字体子集化；复验遗留的三个临时代码包（`p22lazy`/`p22hang`）可按需下架。

> 历史报告不回填：P13 之前落库的报告保持原读数（作为证据），新 run 生效。
