# 服务器验证记录

每次在 ai02 上部署后、按验证清单跑完一轮，把结果写成这里的 `NN-<批次>-YYYYMMDD.md`。
它们是**证据**，不是计划：计划与决策在 `audit-2026-10-09/` 里，审计在 `../audits/`。

| 文件 | 批次 |
|---|---|
| `17-U7阶段一-验收记录-20261013.md` | U7 阶段一 |
| `19-阶段二服务器验证记录-20261014.md` | 阶段二（P2） |
| `23-阶段四服务器验证记录-20261016.md` | 阶段四（报告原文 / promptfoo 对齐） |
| `25-阶段五服务器验证记录-20261019.md` | 阶段五（探针数 / 报告卡 / 计划卡） |
| `26-修复批服务器验证记录-20261019.md` | 修复批（字体内嵌 / 移除拒绝） |
| `27-修复批服务器验证记录-20261019b.md` | 修复批（`originalText` 兜底 / 标注击穿） |

编号与 `audit-2026-10-09/` 里的文档编号是**两套**（那边是计划与决策），所以曾经都堆在仓库根目录。
现在分开了：计划看 `audit-2026-10-09/`，上机结果看这里，一次性审计看 `../audits/`。

> 写记录的纪律：观测按原样记录，**不记得「通过」的那些不算通过**；
> 事后发现当时的判断有误时，在文末追加更正段，而不改动原文（例：`25-…` 的 §6）。
