## 5. 未执行项：§5③ 开闸后端到端复跑 —— **被生成模型 402 阻塞**

`development-status §5-1` 要求「开闸后端到端复用 `p47file` / `p22hang` 复跑一次」。本轮**没有跑成**，原因不在代码：

```
引擎日志：Error from API provider, skipping generation for ContractPlugin:
          API error: 402 Payment Required
          {"error":{"code":"402","message":"Insufficient account balance","type":"insufficient_balance"}}
```

两次独立复现（均 0 探针、生成阶段即失败）：

| run | 结果 |
|---|---|
| `er-2b3c26b2cee040b2bc4a23de7a243abc` | failed / `native_generation_promptfoo_failed`，brief「Test case generation failed for 1 plugin(s): contracts (0/1 tests)」，0 探针 |
| `er-8cae5748814c456294de1d2312dfae45` | 同上，同一 402 |

判定依据（2026-11-03 复核并**更正**）：欠费的不是 DeepSeek，而是**评测用的生成/判定模型 mimo（小米）**。管理员门户「模型配置 → 测试连接」用存储的 key 真打一次，返回：

```
provider_name: mimo | endpoint: https://api.xiaomimimo.com/v1 | model: mimo-v2.6-flash
error: llm http 402: {"error":{"code":"402","message":"Insufficient account balance","type":"insufficient_balance"}}
```

`GET /admin/maclaw/model-default` 与两个企业账号的 `GET /admin/maclaw/accounts/:id/config` 都显示 `current_provider=mimo`、`mimo-v2.6-flash`。而 `.env` / `configs/*.yaml` 里的 `LLM_BASE_URL=https://api.deepseek.com/v1`、`LLM_MODEL=deepseek-chat` 配的是**占位 key**（`LLM_API_KEY` 仅 18 字符、前缀 `sk-pla…`），Go 代码里除启动日志外没有消费点——与评测链路无关。**与 P26a/P26a.1 无关**，也解释了为什么本轮普通 run 会失败（回落共享实例这一步是通的：run 已落库、`engine_base_url` 为空、失败点在生成）。同理，平台判定（judge）也用同一个管理员模型，欠费会一并失败。

**原因**：评测用生成/判定模型账号（mimo / 小米）余额不足（外部计费限制）——充值该账号，或在管理员门户把 provider/key 换成有余额的一套，二者任一即可。
**后果**：本批**没有产生新的代码包端到端证据**；代码策略包运行路径的最后一次真跑仍是 47 号的 `er-cae53c4e…`（向导）与 `er-d73425ee…`（确认），镜像内容与本批一致（本批只改了 compose 与测试）。充值后需补跑一次「`p47file` 向导 + 确认、`p22hang` 失败原因」，预计 3 个 run、约 5 分钟。

## 6. 遗留

1. **mimo（小米）账号余额**（阻塞项，优先级最高）：给该 key 所属账号充值，或在管理员门户换 provider/key；恢复后补跑 §5③，并把 `p47file` / `p22hang` 两条复用为新回归素材。注意判定（judge）同用该模型，欠费时即便用例生成成功也会在判定阶段失败。
2. **开闸值仍未落盘**：引擎 `MACLAW_STRATEGY_CODE_PACKAGES=1` 是本轮用 `sudo env …` 传的，`.env` 里没有该键；任何不带这条 env 的 `docker compose up -d --force-recreate promptfoo-engine` 会把它打回 0（与 P22 的 DNS override 同类陷阱）。§5-1 明确要求落 `.env`，但写 `.env` 属配置写入，需要主理人点头后执行。
3. P26b/c/d（生成 key 按租户、实例级 token、跨租户判据）未做——「共享部署不放代码包」的结论不变，本轮 1 只适用于 ai02。
4. 本批未发现代码缺陷；新增的两条守卫已把「新开关没接进编排」这类事故变成 CI 红灯。
