## 6. 本轮新观察（均未改代码）

1. **引擎测试红**：`patchTablesSource` 非幂等（§2），差 1 个换行；`npm test` / CI 必红，修法是在 strip 时保留/规范化块前换行，或用「块前后各带标记换行」的写法。
2. **上传失败被映射成 503**：上传一个 `entry` 不满足契约的包时，接口返回 `503 {"code":"maclaw_unavailable","error":"maclaw runtime is unavailable"}`，而状态表里同时正确记录了 `rejected` + 可操作原因。根因是 `classifyMaclawError` 只识别 `PromptfooCustomPluginValidationError`，没识别 `EmbeddedPluginValidationError`，落进通用分支。应返回 400/409 + `embedded_*` 码。
3. **`scripts/embedded-build.sh` 的 `-root` 口径与仓库布局不符**：脚本把 `ROOT`（仓库根，外层）传给 `-root`，但 `cmd/embeddedbuild` 期望的是平台目录（`internal/` 与 `promptfoo_engine/` 的父目录）。默认执行会在写 catalog 时失败：
   `stage: write catalog: open …/internal/maclaw/testdata/embedded_plugins.json: no such file or directory`，并会先在仓库根留下一个多余的 `promptfoo_engine/embedded-plugins/` 树。本轮改为手工 `-root <platform_dir>` 才跑通；脚本默认值应改为 `PLATFORM_DIR`。
4. **坏包错误不可诊断**：§5.3 的契约违例最终只表现为 `native_generation_promptfoo_failed` + 「0/2 tests」的通用原因列表，没有指出「哪条用例缺 `vars`/`assert`」。与 53 §7.2 的「404 而不是状态冲突」同类：错误码已区分，但展示层把可操作信息丢了。
5. 内嵌插件不遵守 `n` 时，`num_tests_effective`（按配置算 = 2）与 `total_cases`（插件实际返回 1）会不一致。设计上 `n` 是给插件的参数、不强制，但报告里两个数字并列时会被读成「少跑了一条」。
