## 2. 本轮验证新发现的问题

### 2.1 🔴 P0 · SanitizeMetadata 剥离 `generation_path` → confirm 流报告编译失败

**现象（端到端实测）**：
1. 新建会话 → 发需求（提示词泄露 + 隐私泄露）→ maclaw 生成 plan 卡（`promptfoo_plugin:prompt-extraction` + `promptfoo_plugin:pii`，合法插件）；
2. `confirm` 返回 202（job `pfj-d3e1aa33`）→ engine run `er-2396c793` **succeeded**（plan_c、nte=6、6/6 探针，51.5s）；
3. **但 `maclaw_redteam_reports` 无新行，job 终态 `failed`，error=`engine_execution_failed`，status_text 仍显示「评测完成」** —— run 成功、报告没了。

**根因（代码链 + 实测双重确认）**：
- `redteam/payload_store.go` 的 `isUnsafeMetadataKey`：键名含 `path` 即判不安全 → **`generation_path` 被剥离**（`num_tests_effective` 不含敏感词，存活）；
- `redteam_artifact_service.go CompileReport`：`metadata := SanitizeMetadata(in.Metadata)` 先清洗 → `ValidateReportGenerationMetadata` 校验清洗后的 map：`num_tests_effective=6` 存在而 `generation_path` 缺失 → 按设计返回错误「num_tests_effective is set but generation_path is not」→ **拒绝写报告**；
- 读路径同样被剥离：`reportFromRecord` → `SanitizeMetadata` → 导出报告的 caption 永远显示「未记录」（实测：手工把某报告 metadata 改成 `plan_b` 后导出，HTTP 200 且 caption 为「未记录」而非「字段非法」——写保护 fail-closed 分支实际**永不可达**）。

**影响**：
- 所有走 confirm 流的 native 确认执行都无法产出报告（前端将看到 job 失败，无报告卡）——比 U7 时的「报告不可比」更严重；
- G-4（≥2 份真实 plan_c 报告）无法满足；
- P2-6 的 PDF 口径行、聊天报告卡口径行、写保护三项在报告侧全部失效（engine_runs 侧数据是好的）。

**修复建议**（阶段二补批）：`SanitizeMetadata`/`isSafePayloadMetadataKey` 对 `generation_path`、`num_tests_effective` 显式放行（它们是固定枚举/正整数，安全），或在 CompileReport 校验**先于**清洗。单测缺口：P2-6 的测试直接测 caption/validate 纯函数，未覆盖 SanitizeMetadata 交互层。

### 2.2 🟡 G-3 未达标 · 能力矩阵 20/25 = 80%（阈值 ≥90%）

| 失败 id | 失败形态 |
|---|---|
| beavertails / cyberseceval / xstest | 生成阶段 0/1 用例 → `native_generation_promptfoo_failed` |
| bias（5 个子插件） | 同上（bias:age/disability/… 各 0/1） |
| harmful（24 个子插件） | 同上（chemical-biological-weapons/child-exploitation/… 各 0/1） |

- 失败全部发生在**生成阶段**（LLM 合成 0 用例，`strict:true` 正确 fail-closed），error_brief 可读；
- 引擎日志无底层原因（只有 "Failed to generate tests for X / Generated 0 tests"），**疑似生成模型（mimo-v2.6-flash）对高危害类目的内容策略拒绝或输出不合模板**——非平台代码缺陷，但意味着「26 个合法本地 id」在本环境实际可跑 **20 + 1(policy 需配置) = 21** 个；
- 通过的 20 个全部 `num_tests_effective == fanout`（每个子插件恰好 1 条），P2-4 均摊逻辑精确。
