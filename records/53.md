### 3.1 引擎镜像为什么不是清洁构建（重要）

- 公网（含 npmjs、npmmirror、goproxy 之外的常规站点）全部不可达；mihomo 的 48 个节点全部 `alive=false`，`curl -x 127.0.0.1:17890` 一律超时。
- 发现可达的**内部 npm 镜像** `registry.npm.qianxin-inc.cn`（10.41.200.128），`adm-zip` 等绝大多数包可取；但该镜像的 `@colors/colors` 只有 `1.4.0/1.5.0/1.6.0`，**没有 lockfile 要求的 `1.6.1`**（`node_modules/winston/node_modules/@colors/colors`），`npm ci` 与 `npm install` 都在该包 404 终止。
- 因此引擎镜像用临时 `Dockerfile.localregistry`（构建后已删除、未入库）：以 `evaluating_platform-promptfoo-engine:latest`（上一版）为 build 阶段，注入从内部镜像取到的 `adm-zip-0.6.1.tgz`，再用镜像内的 `tsc -p tsconfig.json` 编译当前 `src/`，runtime 阶段与原 Dockerfile 一致。
- 差异面：只有 `winston` 下嵌套的 `@colors/colors` 版本（1.5.0 vs 1.6.1，纯颜色工具）与两个被 lockfile 移除的 optional peer 包；**其余 600+ 包与上一版逐包一致**。但这不是 CI 会产出的镜像，**网络恢复后必须用 `Dockerfile` 重新清洁构建一次**再谈发布。

## 7. 观察（均未改代码）

1. **`auto_gate.files` / `source_bytes` 恒为 0**：列表里显示「自动关卡：通过 · 0 个文件」。原因是 store 的 `stampEmbeddedGateMetadata` 只写 `embedded_package_id` / `embedded_gate` / `embedded_test_summary`，而 handler 读 `out.Metadata["embedded_files"]`；`source_bytes` 也没有赋值点。属展示层数据缺失，不影响关卡结论。
2. **不存在的 packageId 返回 409 而非 404**：`POST …/embedded-plugins/no-such-pkg/review` 与 `…/request-build` 都回 `409 embedded_state_conflict`「该包状态已被其他人变更」，而源码抽屉对同一 id 回 `404 embedded_not_found`。根因是状态迁移「影响 0 行」统一映射成冲突；对一个从未存在的包，这句提示会误导排查方向。
3. **驳回后重传保留上一版意见**：第 6 步后 state 回到待初审，但 `review_reason` 仍是上一版的「请补充 manifest 的 category 说明」。列名是「最近意见」，保留历史可能是有意的；但专家侧若把它读成当前版本的意见，会困惑，建议 UI 标注「上一版意见」或重传时清空。
4. **测试包留存**：`p28-smoke-plugin`（资源 `2f917792-5682-4d32-9a20-1834ab88e356`，专家 `expert@demo.com`）目前停在 `build_requested`，作为状态机证据与「批了没人建」的真实样本保留。若后续构建批次执行，它会是一个 3 文件的最小插件；不需要时可在那个批次里移除或直接清 DB（本轮未动数据）。

## 10. 更正与后续（2026-11-11，审查修复后）

§7 的三条代码级观察已在本地修复（同一迭代，未上机复验；归 E-6 一并验收）：

1. **`auto_gate.files` / `source_bytes` 恒 0（§7.1）**：`ValidateEmbeddedPluginPackage` 现返回 `EmbeddedPackageStats`（非目录文件数 + `.ts/.js/.mjs` 解压字节），store 的 `stampEmbeddedGateMetadata` 写入 `embedded_files` / `embedded_source_bytes`，上传 handler 读回 `gate.Files` / `gate.SourceBytes`；前端关卡行变为「✓ 通过 · N 个文件 · …」。两个键不含 payload/secret/path 黑名单子串（测试断言）。
2. **不存在的 packageId 返回 409（§7.2）**：`ReviewEmbeddedPlugin` 与 `BuildLifecycleEmbedded` 在状态机之前先查 `GetByPackageID`，无行 → `404 embedded_not_found`，与源码抽屉一致；已存在但状态被并发变更仍是 409（语义不混）。行永不物理删除（`removed` 是状态），因此 nil 即定论。
3. **重传保留上一版 `review_reason`（§7.3）**：采用「UI 标注」方案（保留历史，事件表本就留痕）——`embeddedReviewReasonLabel(state)` 在 `pending_initial_review` 时显示「上一版意见：」，其余显示「意见：」，管理员列表使用该标签；专家侧只在 `rejected` 时展示意见，不受影响。

§7.4（测试包留存）与 §8（未跑烧制、引擎清洁构建）不变，均属 E-6 / 部署环境范围。
