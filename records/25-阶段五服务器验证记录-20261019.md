## 3. 新发现缺陷汇总

### 🔴 P1 · runtime 路径忽略 removed_capability_refs，移除全部插件反而重复执行原计划

- **现象**：见 §5 表。移除操作在 runtime 路径上既不生效也不报错，用户以为移除了 X，实际原样跑全部。
- **影响**：①「移除」承诺失效（用户控制评测范围的唯一手段失灵）；②重复执行浪费配额；③与 §5 判据 5 的 fail-closed 语义直接冲突。
- **修复建议**：`ConfirmPlan` 在落入 runtime 路径**之前**统一消费 `removed_capability_refs`（有移除即视为「需要引擎快速路径语义」，refs 为空时先把 risk_types 归一化成 refs 再走快速路径）；或 runtime 代理透传移除集合。同时在计划卡合成端保证 `selected_capability_refs` 恒定填充（这是分轴显示的数据前提）。

### 🟡 计划卡 refs 填充不稳定（判据 1 的数据前提）

同一 maclaw 会话里，P4 卡带 `["promptfoo_plugin:prompt-extraction","promptfoo_strategy:base64"]`，P5 会话卡 `selected_capability_refs: []`（插件只在 risk_types）。前者驱动快速路径+分轴显示，后者两者皆失。建议在卡合成处做一致性校验。

### 🟢 脚本字段名与实现不一致（§4）

`25-部署与验证-阶段五.sh` 判据 4 找 `card_type`，实现是 `evaluation_event_type`——脚本需同步，否则按脚本跑会误报。

## 6. 事后处置（2026-10-19，写入方：平台侧）

> 本节在收到本记录后追加，不改动上面任何原文。

### 6.1 🔴 P1 · runtime 路径忽略 `removed_capability_refs` —— 已修（改为 fail-closed 拒绝）

原文说的没错：计划卡 `selected_capability_refs` 为空时 confirm 落入 runtime 路径，
那是唯一消费移除集合的地方之外，于是「移除全部插件」被接受并把原计划完整跑了一遍。

**修法**：在落入 runtime 路径**之前**判断 —— 若请求带了移除项、而这张卡没有可逐项调整的能力，
返回 **409 `plan_capability_removal_unsupported`**，**不执行**。理由与项目一贯口径一致：
执行一张与用户选择不符的计划，是这套机制存在的目的所要防止的静默降级。

**没有做**记录建议的另一半（把 `risk_types` 归一化成 refs 再走快速路径）：`risk_types` 是风险
类别（jailbreak / prompt_injection），不是插件 id，映射过去是**猜**，而猜错的结果是跑一批
用户没选的插件。计划卡 refs 填充不稳定是 maclaw 侧的问题（§3 的🟡），应由那边统一填充。

**测试**：`TestConfirmPlanRefusesRemovalsItCannotHonour` 走 HTTP handler；反证已跑
（去掉该闸 → 202 + 计划被执行，正是本轮观测到的现象）。

### 6.2 🟡 计划卡 refs 填充不稳定 —— 平台侧只能兜住，不能修复

本记录 §5 已定性。平台侧现在的行为是：refs 为空的卡**渲染不出 chip 和 ×**（`planRefGroups`
只读 refs），因此正常用户碰不到 6.1 那个路径；API 调用会被 409 拒绝。真正的修复在 maclaw
的计划卡合成端 —— 即「卡上选了什么，`selected_capability_refs` 就必须写什么」。

### 6.3 🟢 脚本字段名 —— 已修

`25-部署与验证-阶段五.sh` 的判据 4 现在同时接受 `card_type` / `evaluation_event_type` /
`response_source` 任一为 `report`，并额外打印**消息 id**：

- `engine-report:<report_id>` —— 平台合成（本批新增的路径）；
- `msg_…` —— maclaw 自己写的报告消息（运行时路径）。

本轮 §4 观测到的卡片 id 是 `msg_1740e6cf`，也就是说**它很可能是 maclaw 写的**，而不是平台
合成 —— 那么平台合成的路径本轮**并未被验到**。下一次跑脚本时看那个 id 就能分辨。

### 6.4 PDF 字体乱码 —— 已修（用户现场反馈，未在脚本判据里）

报告的 PDF 声明 `/BaseFont /STSong-Light` + `/Encoding /UniGB-UCS2-H` 却**没有字体程序**，
浏览器没有这个字体，所以整篇乱码。现已内嵌字体（见 `maclaw-current-state.md` 同名一节），
代价是每份 PDF ≈ 1.6 MB，并已用 pypdf 解析真实 PDF 验证中英文抽取全部命中。
