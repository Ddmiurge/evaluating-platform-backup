## 5. 发现并修复：引擎 `docker restart` 后崩溃重启

**现象**：`docker stop` + `docker start`（或 `docker restart`）引擎后，容器进入 `restarting/unhealthy` 循环，日志：

```
[engine] fatal: ConnectionFailed("Unable to open connection to local database
  /home/node/.promptfoo/promptfoo.db: 14")
```

**根因**（scrap 容器复现）：Docker 的 tmpfs 在 **create** 时挂成 `drwxrwxrwt root:root`，在 **start** 时却挂成 `drwxr-xr-x root:root`；引擎以 uid=1000 运行，写不了 0755 的 `/home/node/.promptfoo`，SQLite 打不开就退出，restart 策略再拉起 → 崩溃循环。共享引擎与专属引擎的 tmpfs 配置相同，主机重启/`docker restart` 都会中招。

**修复**（`docker-compose.yml`，两个引擎同改）：

```yaml
- /tmp:rw,noexec,nosuid,size=256m,uid=1000,gid=1000,mode=1777
- /home/node/.promptfoo:rw,noexec,nosuid,size=512m,uid=1000,gid=1000,mode=1777
```

**验证**：

```
docker restart ep_promptfoo_engine ep_promptfoo_engine_p8test
→ 两者 running/healthy
→ 容器内 /home/node/.promptfoo = drwxrwxrwt node node
→ stop/start 后不再崩溃，账号探活从 unreachable 恢复 ok
```

> 该项是本轮新增的本地 compose 改动，**未提交**；远端 compose 仍是原 tmpfs 配置。
