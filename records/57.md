## 6. 新发现：finalize 之后重启引擎会丢目录（重要）

**机制**：`-finalize` 成功后会 `os.Remove(index.json)`（维持「index 存在 ⟺ 有待定格批次」），而卷挂载后引擎开机只读这个文件（`patch-embedded-plugins.mjs` 的注册块）；卷内容遮蔽了镜像内 `COPY` 的树，镜像里的旧 index 不再可达。

**实测**：

1. 判据①结束（index 已删）后重启 `ep_promptfoo_engine` → 容器 healthy，但进程内目录为空。
2. 向导仍列出 4 个插件（backend 读 testdata 文件），提交 `p28-vol-check`：
   - `er-0fcce457b6194776b3fe40b1f70b0ba0` **168ms 失败**，`native_generation_promptfoo_failed`：
     `Invalid plugin id "p28-vol-check". Custom plugins must start with file:// or use a built-in plugin.`
3. 恢复：`-stage`（`batch-20261116T082409Z`，4 包）+ 重启引擎 → `er-64653f72acaf4a2a8dd675da3406b213` succeeded 1/1 / 3192ms。

**影响**：任何不经 `-stage` 的重启（宿主机重启、`docker compose up -d` 改无关配置、单独 restart）都会让引擎目录归零，而向导/MCP 照样展示 —— 正是设计要避免的「一个事实两个视图」。另外 `-stage` 会把 `testing/approved/disabled` 全部重 stage（正确），但 `-finalize` 随后又删除 index，两个用途共用一个文件是冲突点。

**建议**：把「持久目录」与「批次标记」分开（如 `catalog.json` 常驻、`batch.json` 只存待 finalize 的批次），或 finalize 保留 index、另设 pending 标记。

**附带**：`embedded-build.sh` 只 recreate 共享 `promptfoo-engine`，不 recreate `promptfoo-engine-p8test`；多引擎部署时另一实例会继续用旧目录（本轮已手工重启 p8test）。
