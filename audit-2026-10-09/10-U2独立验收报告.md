## 2. ① 契约测试反向验证（本次核心补做）

### 方法
`09` 文档登记的原话是「契约测试的**反向验证（加假方法应变红）未由 QA 独立复现**」。本次做**端到端注入**，而非只测 helper。

### 过程与结果

**步骤 1｜正向基线**
```
go test ./internal/maclaw/ -run TestGatewayRouteContract -v
```
→ 3 用例全PASS：主断言（4 个接口子测试）+ `DetectsUnregisteredMethod` + `DetectsStaleRegistration`。

**步骤 2｜只加接口方法**（`client.go:647` `EvaluationGateway` 注入 `QAProbeGhostMethod(context.Context) error`）
→ **编译器先拦**（双保险生效）：
```
internal/maclaw/provider.go:110:10: cannot use c.WithInstanceID(instanceID)
  (value of type *MaclawSrvClient) as GatewayClient value:
  *MaclawSrvClient does not implement GatewayClient (missing method QAProbeGhostMethod)
```
共10+ 处报错，横跨 `provider.go` / `runtime_kind.go` / `provisioner_test.go` / `redteam_tool_bridge_test.go` / `resource_projection_test.go`。

**步骤 3｜补齐两个实现后**（`*Client` + `*MaclawSrvClient` 各加一个空实现）
→ **契约测试主断言按预期变红并点名**：
```
--- FAIL: TestGatewayRouteContract/EvaluationGateway
    gateway_contract_test.go:164: GatewayClient contract drift:
      - interface method "QAProbeGhostMethod" is not registered
        — please specify its HTTP route or an 'exempt: <reason>' entry
```

**步骤 4｜恢复现场**
`git checkout --` 还原 3 个文件 → `git status` 干净、无 `QAProbe` 残留、测试恢复 `ok`。

### 结论
契约测试是**真实有效的双向安全网**，可放心作为 U3 拆包 / 收窄接口的前置条件。
`08` §5纪律第 4 条「没有 T3.1 契约测试就禁止动 client.go 的方法集合与包边界」的前提**已满足**。

### 方法论沉淀（重要）
验证「护栏测试是否真会红」必须做**端到端注入**（改真实接口并补齐实现）。
只测 fixture（如现有的 `driftFixture`）不够——fixture 只证明 `contractIssues` 这个 helper 逻辑正确，
不能证明**真实接口**漂移时会被抓到。
