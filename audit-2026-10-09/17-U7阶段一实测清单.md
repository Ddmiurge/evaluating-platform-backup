## 0. 测前必读 · 两个「不是阶段一引入」的已知问题

### 0.1 🔴 `direct` 是表单默认值 → 不选策略直接提交会白跑一个被丢弃的维度

| 事实 | 位置 |
|---|---|
| 提交时 `strategies: (values.strategies ?? ['direct'])` | `frontend/src/pages/enterprise/EngineEvalPage.tsx:283` |
| `direct` 在前端选项表里（`{ id: 'direct', name: '直接攻击' }`） | `frontend/src/services/engineEval.ts:248` |
| `direct` 属 `PLAN_A_ONLY`（Plan C 下被丢弃） | `promptfoo_engine/src/runner/nativeStrategyMap.ts:60` |

**现象**：用户**一个策略都不选**直接提交 → 前端下发 `['direct']` →
Plan C 的 `resolveNativeStrategies` 把它归入 `planAOnly` → **不施加该手法**，
但 run 仍然会跑（不是失败）。

**这不是 bug，是阶段二的待修项**（D4 已定案：前端不显示 + 规划时选不到，
且要把默认值改成 `[]`，见 `16` §6-A.2）。**阶段一不改代码。**

> ✅ **实测时必须显式选至少一个 `NATIVE` 策略**（如 `jailbreak`、`base64`、
> `crescendo`），否则你测的是「什么都没施加」的 run，
> 第 4 项（12 维度丢弃）会与「策略选对了没」混淆。
> 若你**故意**要复现这个现象：那是 D4 的验收用例，不是阶段一的。

### 0.2 12 个平台维度在 Plan C 下会被丢弃（12 / 前端可见 9）

`nativeStrategyMap.ts:59-68` 的 `PLAN_A_ONLY` 共 **12** 个 key：

```
direct  role-play  encoding  multi-turn  assumed-knowledge
few-shot  many-shot  translate  otherEncodings  simba  retry  mathPrompt
```

**前端只暴露 9 个**（`simba` / `retry` / `mathPrompt` 已在 Phase 3 §6.1.2
移出目录，用户本来就选不到）。

**行为**：这些维度**不是报错，是静默不施加**——`nativeRedteam.ts:784-792`
会 emit 一条 `status_text`：
> `原生生成（N 个平台维度不参与）`

**为什么是静默**：promptfoo 对不认识的策略 id 会 throw，而丢弃会低报实际施行的
能力，所以代码选择「不转发 + 明说数量」。这是**有意设计**，不是遗漏。

>   ? { onTerminal: async (): Promise<void> => void (await cleanupPromptfooRunArtifacts()) }

> `nativeGenerationEnabled(process.env)` = `parseBool("1")` = `true`，

> 它只兜底「重启后」，兜不住「run 结束到重启之间」这段窗口。第 3 项测的就是这段。

> 而 U8 要挂 `graderGuidance` → `config` 存在 → `undefined.trim()` → **整个 run 崩**。
> 所以对 `policy` **不挂 rubric**，改由 promptfoo 自己的 PolicyPlugin grader 判。
>
> ⚠️ **额外注意**：`policy` 还需 `config.policy` 策略文档，**平台不提供** →
> 选它**可能 0 用例**。`15` §4 已登记。这是已知缺口，不是阶段一引入的。

## 4. 回滚（**一个变量，不改代码**）

```bash
# 在 .env 里加一行，然后强制重建容器
echo 'PROMPTFOO_ENGINE_NATIVE_GENERATION=0' >> .env
docker compose up -d --force-recreate promptfoo-engine
```

**无需改代码、无需数据迁移、无需清库**。
`env.ts:96-97` 承诺的「一个变量即可回滚」在部署侧同样成立：
`parseBool` 把「未设置」与「拼错」都映射为 `false` → 回到 Plan A 这个已知good 路径。

**回滚后的副作用**：`onTerminal` 清理钩子**不再挂载**（`server.ts:60-62` 的条件），
但 Plan A 不写任何东西，所以不需要它。专家自定义插件/策略包会重新被拒
（`custom_plugin_requires_native_generation`），这是**预期行为**。
